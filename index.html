Engineering notes

A recent production investigation. One failing sync run turned out to hide three separate problems.

Finding 1

A duplicate row broke an entity load

Hibernate raised “duplicate row found” while loading an eagerly fetched association. Lesson: check join mappings and the data under them, not just the query that triggered the load.

Finding 2

The real error was masked

A catch block cast every exception to one custom type and threw a ClassCastException instead. Fix: catch specific types and always log the original exception with its stack trace.

Finding 3

Cleanup failed on a foreign key

The compensation step deleted parent rows while child rows still pointed at them, so rollback never finished. Fix: delete children first, flush, then delete the parents.
